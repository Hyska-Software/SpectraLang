Chapter 1

1. What SpectraLang is and how to install it

SpectraLang is a statically typed language and toolchain for readable general-purpose programs, numerical work, tensor workloads, and production-oriented AI/ML experiments. A source file uses the .spectra extension. The compiler pipeline includes lexical analysis, parsing, semantic validation, IR lowering, and a Cranelift-based execution path.

The language favors explicit types at boundaries, familiar control flow, qualified standard-library imports, and error values that can be inspected through patterns. The runtime includes ordinary I/O, collections, filesystem and environment helpers, tensor and ML facilities, a local serving baseline, and concurrency primitives.

Install from a checkout

On Windows, install Rust and Cargo, clone the repository, then build the CLI in debug mode. The repository-local executable is the most reliable binary while developing the language.

PowerShell
cargo build -p spectra-cli
target\debug\spectralang.exe --version

Version and maturity

This guide targets version 0.2.7. Stable features are validated through the normal CLI path. Beta features are implemented but may have execution or API boundaries. Deferred items are not promises of the current release.

stable is safe to learn first. beta needs extra validation. deferred is deliberately outside the current surface.

Installation checklist

  1. Install Rust with the stable toolchain and ensure cargo is on PATH.
  2. From the repository root, build spectra-cli and use target/debug/spectralang.exe on Windows.
  3. Run spectralang --help and a small check command.
  4. Keep the compiler, standard library, examples, and tests from the same checkout when validating a language change.

Chapter 2

2. Your first program and the CLI workflow

A SpectraLang program normally has a module declaration and a public main function. A successful integer return value is the process exit code. The following is the canonical 20-line quickstart shipped in examples/syntax_quickstart.spectra.

examples/syntax_quickstart.spectra
module syntax_quickstart
from std.io import println
func welcome(name: string) returns string {
    return f"Ola, {name}!"
}
public func main() returns int {
    let name    = "SpectraLang"
    let message = welcome(name)
    println(message)
    let total = 0
    for item in [1, 2, 3] {
        total = total + item
    }
    if total > 5 and not total == 0 {
        println("sintaxe clara")
    } else {
        println("continue explorando")
    }
    return 0
}

The block demonstrates a module, named import, function with returns, f-string, mutable local, array iteration, boolean operators, and an explicit exit code.

PowerShell — inspect, format, check, run
spectralang fmt --check examples\syntax_quickstart.spectra
spectralang check examples\syntax_quickstart.spectra
spectralang run examples\syntax_quickstart.spectra
spectralang lint examples\syntax_quickstart.spectra

Chapter 3

3. Source files, modules, imports, visibility, and project layout

A source file is a module when it begins with module name. A project may contain one entry file or a directory tree described by spectra.toml. Keep each module focused, expose a small public surface, and use imports to make dependencies visible.

Module forms

Module and import forms
module app.main

from std.io import println
from app.geometry import Point, distance
import std.math as math

public func main() returns int {
    let origin = Point { x: 0 y: 0 }
    println(math.float_to_string(distance(origin, origin)))
    return 0
}

Use from package.module import Name for named imports, import package.module for a qualified module, and as for an alias. Keep qualification when it improves clarity, especially for large standard-library modules.

Visibility

FormMeaning
publicExports a function, record, enum, trait, constant, or other supported declaration to importing modules.
No visibility keywordModule-internal declaration. It is available to the defining module and its implementation details.
public from module import NameRe-exports an imported name from the current module.
Public record fieldsFields intended for construction or access outside the defining module must be marked public where the declaration requires it.

Recommended project layout

Project tree
my_app/
  spectra.toml
  spectra.lock
  src/
    main.spectra
    model.spectra
    io.spectra
  tests/
    smoke.spectra
  packages/
    shared/
      spectra.toml
      src/

Declarations are resolved from the project source directories and workspace members. Avoid relying on implicit file order. The manifest and lockfile are the source of truth for package builds.

Chapter 4

4. Variables, mutability, primitive types, literals, strings, and operators

Local bindings use let. A binding is immutable by default; use let mut when the value will be assigned again. Type annotations are written after a name with a colon. Type inference is useful for local expressions, while public APIs should state their types.

Bindings and literals
let count: int = 3
let mut total = 0
total = total + count

let enabled: bool = true
let ratio: float = 0.75
let letter: char = 'S'
let title: string = "SpectraLang"
let nothing = null
let message = f"{title} has {count} items"

Primitive types and aliases

TypeValues and use
booltrue or false.
intSigned integer used by ordinary counters and indexes.
floatFloating-point value for numerical computations.
charA character literal such as 'a'.
stringUTF-8 text value with standard string helpers and f-string interpolation.
unitThe no-value result of a procedure-like function without a declared return.
Numeric aliasesThe compiler also exposes validated numeric aliases used by tensor, ABI, and interop surfaces. Prefer the documented alias at an external boundary.

Strings and interpolation

Use double quotes for strings and single quotes for characters. An f-string begins with f and evaluates expressions inside braces. Keep interpolation expressions small; move domain logic into a named function.

Operators

FamilyOperators
Arithmetic+, -, *, /, %
Comparison==, !=, <, <=, >, >=
Booleanand, or, not
Bitwise&, |, ^, shifts, and complement where supported by the operand type.
Assignment= assigns to a mutable binding; compound assignment forms are available for supported numeric values.
Access. accesses a field or method; :: qualifies an enum variant or associated name.
Readability rule: write if not ready, left and right, and first or fallback. These words are part of the canonical surface and are easier to scan than punctuation-heavy alternatives.
Migration warning: older reports or source files may use fn, struct, pub, elif, unless, arrow return types, fat-arrow expressions, or statement semicolons. New code in this guide uses func, record, public, else if, if not, returns, when ... then, and semicolon-free blocks.

Chapter 5

5. Functions, return types, implicit returns, closures, and function types

Declare a function with func. Parameters have name: type form. Use returns type for the return type. A function with no explicit return type is procedure-like and returns unit. Explicit return statements are best at early exits; a final expression may be used as the value of a block where the grammar permits it.

Functions and closures
func square(value: int) returns int {
    value * value
}

func apply_twice(operation: (int) returns int, value: int) returns int {
    operation(operation(value))
}

public func main() returns int {
    let offset = 4
    let add_offset = |value: int| value + offset
    return apply_twice(add_offset, 3)
}

Closures use pipe parameters and may capture values by value. Mutable or reference captures are part of the beta closure surface and should be checked against the current maturity policy before use in production code. Function types can be passed as arguments, stored in records, and returned from functions.

Return-path rules

  • A function declared with a non-unit return type must produce that type on every reachable path.
  • return value exits the current function; it does not silently exit an enclosing closure.
  • A match expression can produce a value when every arm produces a compatible type.
  • Use explicit annotations when inference would hide a public contract or a tensor shape.

Chapter 6

6. Conditions, loops, ranges, break, continue, switch, and match

Blocks are delimited by braces and statements do not require semicolons. Conditions use if, else if, and else. The readable negation form is if not condition.

Control flow surface
func describe(value: int) returns int {
    if value < 0 {
        return -1
    } else if value == 0 {
        return 0
    } else {
        return 1
    }
}

func sum_until(limit: int) returns int {
    let mut total = 0
    for value in 0..limit {
        if value == 3 {
            continue
        }
        if value > 8 {
            break
        }
        total = total + value
    }
    return total
}

Loop forms

FormUse
for item in collectionIterate through an array, range, or supported iterable.
while conditionRepeat while a boolean condition remains true.
while let pattern = expressionRepeat while a pattern continues to match.
loopRepeat until an explicit break.
do { ... } while conditionExecute the body once, then test the condition.

Ranges use the range standard-library model and can be used directly with for. Confirm endpoint behavior for a range constructor before relying on it for indexes; prefer collection length and checked access at external boundaries.

switch for statement-oriented branching

Switch cases
switch day {
    case 1: {
        println("Monday")
    }
    case 2: {
        println("Tuesday")
    }
}

match for value-producing patterns

Match arms
let label = match score {
    when 100 then "perfect",
    when 80 | 90 then "ready",
    otherwise then "keep practicing"
}

Patterns can match literals, enum variants, tuples, records, nested structures, and OR alternatives. An exhaustive match is easier to maintain than a chain of unchecked conditions.

Chapter 7

7. Arrays, tuples, records, enums, pattern matching, and destructuring

Arrays and tuples

Array literals use square brackets and hold a sequence of compatible values. Tuple literals use parentheses and can hold a fixed group of values with different types.

Arrays, tuples, and destructuring
let scores = [10, 20, 30]
let pair = ("SpectraLang", 0.2)
let(name, version) = pair
let first = scores[0]

Records

A record names fields and is useful for data with stable structure. Construct it with the record name followed by a field initializer block. Use public record for a record exported by a module.

Record declaration and construction
public record User {
    public name: string
    public active: bool
}

let user = User {
    name: "Ada"
    active: true
}
let is_active = user.active

Enums and variants

Enums model a closed set of variants. Variants may be unit-like, tuple-like, or record-like. Qualify a variant with EnumName::Variant when ambiguity would otherwise be possible.

Enum variants and matching
enum Message {
    Quit
    Move { x: int y: int }
    Write(string)
}

func weight(message: Message) returns int {
    match message {
        when Message::Quit then 0,
        when Message::Move { x y } then x + y,
        when Message::Write(text) then std.string.len(text)
    }
}

Destructuring binds the contents of a tuple, record, or variant to local names. Rename a field in a pattern when the local name would otherwise collide. Pattern syntax is available in let, if let, while let, and match.

Chapter 8

8. Traits, impl, generics, dyn Trait, and operator overloading

Traits describe behavior shared by multiple types. An impl block supplies methods for a type or implements a trait for a type. Generic parameters express reusable algorithms without erasing the type contract.

Trait and implementation
trait Summarize {
    func summary(self) returns string
}

record Report {
    title: string
    score: int
}

impl Summarize for Report {
    public func summary(self) returns string {
        return f"{self.title}: {self.score}"
    }
}

Generic functions and types

Generic function
func first<T>(items: [T]) returns T {
    return items[0]
}

func show(value: dyn Summarize) returns string {
    return value.summary()
}

Use dyn Trait for a trait object when dynamic dispatch is the right boundary. Generic dispatch is usually preferable when the concrete type can remain known to the compiler. Current generic validation includes type parameters, constraints, generic records and enums, and trait-object calls.

Operator overloading

Supported operators can be provided through the corresponding trait or operator implementation surface. Keep overloads unsurprising: addition should be additive, comparisons should be stable, and domain-specific transformations should normally remain named methods.

Chapter 9

9. Option, Result, if let, while let, and error propagation

Use Option when a value may be absent and Result when an operation may succeed or fail. Both are enum-style values and are meant to be inspected with patterns rather than hidden behind null checks.

Option and Result patterns
func find_score(value: int) returns Option<int> {
    if value > 0 {
        return Option::Some(value * 10)
    }
    return Option::None
}

func read_score(value: int) returns Result<int, string> {
    if value >= 0 {
        return Result::Ok(value)
    }
    return Result::Err("score must not be negative")
}

func use_score(value: int) returns int {
    if let Option::Some(score) = find_score(value) {
        return score
    }
    return 0
}

Pattern-oriented control

  • if let pattern = expression executes a branch when the pattern matches.
  • while let pattern = expression repeats while values keep matching.
  • match can transform either type into a value or handle every variant.
  • Return a Result from a helper when its caller needs to decide whether to retry, report, or recover.

The current language baseline favors explicit pattern handling. Use the standard-library std.option and std.result helpers for construction and common transformations. Error codes from the compiler and CLI are described in the quick reference; runtime failures should carry a meaningful message at the boundary where they are detected.

Chapter 10

10. Async/await and structured concurrency beta

Beta boundary: async functions, await, the reactor, structured task surfaces, streams, async standard-library integration, async trait objects, and formal Send/Sync diagnostics are implemented validation tracks but remain beta. Validate the target platform and fixture before treating an async workflow as a production contract.

Declare an async function with async func. Await an async result with await. Structured concurrency keeps child work associated with a parent scope so cancellation and completion can be reasoned about together.

Async surface
async func read_value(value: int) returns int {
    return value
}

async func combine() returns int {
    let left = await read_value(17)
    let right = await read_value(25)
    return left + right
}
Validation fixture: tests/validation/126_async_stdlib_surface.spectra checks the current async standard-library surface. Related fixtures cover lowering, early return, nested blocks, streams, structured concurrency, async trait objects, and runtime block-on behavior.

For deterministic local concurrency that does not require the beta async language model, use the stable std.concurrent task, channel, counter, and pipeline helpers described in chapter 11. The local std.serve baseline is also separate from HTTP and is not the incomplete spectra.api surface.

Chapter 12

12. Tensor programming, autodiff, and AI/ML

SpectraLang's AI/ML baseline is built around explicit tensor handles, validated operations, deterministic execution options, automatic differentiation, model helpers, export paths, and runtime observability. The stable baseline is intentionally explicit: use standard-library tensor calls today and treat broader first-class tensor syntax as beta.

Tensor lifecycle and shapes

Tensor construction and cleanup
import std.tensor as tensor

public func main() returns int {
    tensor.free_all()
    let features = tensor.reshape(tensor.full_f(4, 1.0), 4, 1)
    let labels = tensor.full_f(4, 2.0)
    let prediction = tensor.add(features, labels)
    let count = tensor.len(prediction)
    tensor.free_all()
    return count
}

Tensor operations validate rank, shape, dtype, layout, and device compatibility where the current operation contract requires it. Device placement includes CPU and an optional wgpu path when the feature and host support it. Track allocations with tensor lifecycle helpers and the runtime memory report.

Autodiff and diff blocks

Differentiable region
let loss: Tensor<float, rank0> = diff {
    let prediction = tensor.mul(weight, input)
    tensor.mean_t(tensor.sub(prediction, target))
}

A diff { ... } expression marks a differentiable region and produces a scalar tensor loss for the current baseline. Keep I/O, metadata, and lifecycle operations outside the block. Unsupported graph operations produce stable diagnostics instead of silently creating a partial gradient.

Datasets, training, and export

  • Represent features and labels as tensors with explicit shapes and dtypes.
  • Use deterministic seeds and record preprocessing decisions for reproducibility.
  • Compose model calls with losses and optimizer steps such as the validated std.ml.linear, mse_loss, and sgd_step path.
  • Export a text or model artifact only after evaluation and lifecycle cleanup have completed.
  • Use the checked-in examples under examples/ai/ for linear and logistic regression, transformer inference, ONNX export, RAG retrieval, evaluation reports, and graph fusion.
AI validation fixture: examples/ai/linear_regression_train_export.spectra is checked as part of this guide's validation. A full project validation is available under tests/projects/valid/integrated_ai_tensor_autodiff.

ONNX, transformer primitives, RAG, evaluation, guardrails, and monitoring

ONNX export and transformer primitives are supported through validated AI examples, not as a promise that every external model format or backend is interchangeable. RAG examples separate retrieval, context assembly, and generation boundaries. Evaluation examples record metrics and reports. Guardrails cover input/output checks and policy decisions. Monitoring should expose latency, errors, memory pressure, device transfers, drift signals, and reproducibility metadata.

ConcernRecommended baseline

Chapter 13

13. Python, Rust, C ABI, and .npy interoperability

The interop baseline is deliberately small and deterministic. Python can invoke a Spectra program through the CLI/JIT boundary. Rust can use the spectra-interop crate. A stable C ABI header and sample are provided. Tensor exchange uses NumPy .npy version 1.0 for one-dimensional little-endian f64 arrays in C order.

BoundaryRepository surfaceValidation
Pythonpython/spectra_bridge.py and python/demo_phase8.pypython python\demo_phase8.py
Rusttools/spectra-interop, TensorF64, and the Rust FFI samplecargo test -p spectra-interop; cargo run -p spectra-interop --example rust_ffi_sample
Ctools/spectra-interop/include/spectra_interop.h and examples/c_ffi_sample.cBuild the release library and compile with LLVM clang.
NumPyPortable .npy v1 round-trip for little-endian f64, one dimension, C orderUse the Python demo and Rust interop tests.

Free memory using the allocator that owns it. C callers must use spectra_interop_f64_array_free for arrays returned by Spectra. Paths cross the ABI as UTF-8 byte pointers with explicit lengths. Broader formats such as .npz, safetensors, checkpoints, and generalized model interchange are outside this current baseline.

Chapter 14

14. Packages, manifests, workspaces, lockfiles, registries, and offline workflows

A package project is described by spectra.toml. The manifest declares the project name, exact version, entry source, source directories, workspace members, and dependencies. A generated spectra.lock records the resolved graph, source, revision, checksums, and manifest hashes.

spectra.toml
[project]
name = "my_app"
version = "0.1.0"
entry = "src/main.spectra"
src_dirs = ["src"]

[workspace]
members = ["packages/core"]

[dependencies]
core = { version = "0.1.0" path = "packages/core" }

Dependency sources

  • Path: local packages in the workspace or a nearby checkout.
  • Registry: packages installed into the local Spectra package cache.
  • Git: a repository, tag or revision, and a checksum recorded in the lockfile.
  • Catalog: a project-configured package index used by explicit catalog commands.

Versions use exact semantic version triples in the current baseline. Do not assume range solving, hosted registry authentication, or implicit remote catalog synchronization. Package compatibility is checked before installation or compilation.

Reproducible and offline builds

Locked offline workflow
spectralang package lock --root .
spectralang package fetch --offline --locked --root .
spectralang package check --offline --locked --root .
spectralang package test --offline --locked --root .

Restore spectra.lock, .spectra/git, and .spectra/packages as one cache unit. --locked rejects a missing or changed graph. --offline forbids network resolution and reports a package-aware cache diagnostic when a required revision or payload is absent.

Package command family

Use package build, check, run, test, bench, doc, add, update, and fetch. Catalog operations include catalog add, list, sync, and remove. The package author tutorial and package-manager reference remain further reading.

CLI commands and process exit codes

Primary commands are compile, check, run, lint, bench, repl, new, release-info, package, db, and fmt. A successful program returns 0 by convention. A nonzero explicit int from main is the program's failure or application-specific status. CLI parse, compilation, and runtime failures are reported by the CLI with a nonzero process status and a diagnostic; use JSON or SARIF output when a calling tool must classify them.
